## Source choices and limits

### Astronomy Engine

Use the C files from release `v2.1.19`, rather than the moving `master` branch. The [original LICENSE](https://github.com/cosinekitty/astronomy/blob/v2.1.19/LICENSE) permits copying, modification and distribution provided the license text accompanies copies or substantial portions. The [C documentation](https://github.com/cosinekitty/astronomy/tree/v2.1.19/source/c) describes the API and integration. Compute topocentric positions from the device's UTC time and the observer's location.

### Stars

HYG v4.1 was selected for the first release. It provides J2000 RA/Dec, magnitude, `hr`, proper names, Bayer/Flamsteed designations (`bf`, `bayer`, `flam`) and constellation (`con`), as described in the [producer's README](https://github.com/astronexus/HYG-Database/blob/c7f7f883fe678cc7680169a50ccd7dcc49b060ce/hyg/README.md). The [`stars.tsv`](../assets/sky/stars.tsv) asset derives from the CSV at the pinned commit, filters to magnitude 6, retains the identifiers needed for constellation lines and is distributed under CC BY-SA 4.0 with Astronexus attribution. Asset SHA-256: `a97e2e88ceca9e65c972e3225954723711f74764cdec8bb5ced15eff2f2a43e3`. This license does not require changing the license of the independent app code.

The [Yale Bright Star Catalog v5](https://tdc-www.harvard.edu/catalogs/bsc5.html) contains 9,110 entries and reaches approximately magnitude 7. A [JSON conversion](https://github.com/brettonw/YaleBrightStarCatalog) also supplies common names and Bayer designations; its [LICENSE](https://github.com/brettonw/YaleBrightStarCatalog/blob/master/LICENSE) is MIT. No LICENSE file for the original Yale catalog was found in the Harvard distribution. The converter's MIT license alone does not establish redistribution rights for the source data. A public release should use HYG's explicit license or first clarify the rights to the particular Yale file it would redistribute.

### Deep-sky objects

**Selected source:** [OpenNGC](https://github.com/mattiaverga/OpenNGC/tree/36cb178a0f69dba8bfc03a99c10512831edf1c6b) by Mattia Verga, at the commit pinned above. The [README at that commit](https://github.com/mattiaverga/OpenNGC/blob/36cb178a0f69dba8bfc03a99c10512831edf1c6b/README.md) states CC BY-SA 4.0 for the database; the [original license text](https://raw.githubusercontent.com/mattiaverga/OpenNGC/36cb178a0f69dba8bfc03a99c10512831edf1c6b/LICENSES/CC-BY-SA-4.0.txt) was also checked. Coordinates are J2000. According to the [field guide](https://github.com/mattiaverga/OpenNGC/blob/36cb178a0f69dba8bfc03a99c10512831edf1c6b/NGC_guide.txt), the CSV files contain type, magnitude, angular size, Messier number and common names. The [addendum description](https://github.com/mattiaverga/OpenNGC/blob/36cb178a0f69dba8bfc03a99c10512831edf1c6b/README.md) says M40 and M45 appear only in `addendum.csv`; both files are needed to import all 110 Messier entries.

The [`deep_sky.tsv`](../assets/sky/deep_sky.tsv) asset contains 605 objects: all 110 Messier entries, followed by objects with a common name or V magnitude of at most 10, excluding single/double stars, novae and unclassified entries among the extras. The [`build_deep_sky.py`](../tools/catalog/build_deep_sky.py) conversion retains identifier, type, J2000 coordinates, V magnitude, size and names; the original CSV is not committed. Current asset SHA-256: `55d0d300c7443cc96354001efa0661683303c55e1a485cf7345ec664f3b7452a`.

To provide 110 Messier labels, the conversion explicitly associates M102 with NGC5866. [OpenNGC treats M102 as a duplicate of M101](https://raw.githubusercontent.com/mattiaverga/OpenNGC/36cb178a0f69dba8bfc03a99c10512831edf1c6b/database_files/addendum.csv), while the [NGC5866 entry](https://raw.githubusercontent.com/mattiaverga/OpenNGC/36cb178a0f69dba8bfc03a99c10512831edf1c6b/database_files/NGC.csv) notes that it might be M102. This choice appears in the TSV header and must not be presented as historical certainty.

The derivative remains separate from the MIT code and ships the [CC BY-SA 4.0 notice](../assets/sky/LICENSE-CC-BY-SA-4.0.txt). OpenNGC's README lists NED, HyperLEDA, SIMBAD, HEASARC and Harold Corwin among the original sources; the distributed credits must retain those acknowledgments.

### Constellation lines

**Selected source:** d3-celestial's [`constellations.lines.json`](https://github.com/ofrohn/d3-celestial/blob/7e720a3de062059d4c5400a379146a601d9010e0/data/constellations.lines.json) at the pinned commit. The [d3-celestial README](https://github.com/ofrohn/d3-celestial/blob/7e720a3de062059d4c5400a379146a601d9010e0/readme.md) names the IAU constellation page as its source, with changes by Olaf Frohn. The [IAU page](https://www.iau.org/IAU/Astronomy-FAQs/Constellations.aspx) explicitly states that its charts, produced with *Sky & Telescope*, are [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). It credits Roger Sinnott and Rick Fienberg for the charts and Alan MacRobert for the figure drawings. The same page clarifies that the IAU officially defines **boundaries**, not segment figures: the segments are a western representation, not an IAU standard.

This provenance chain is documented by d3-celestial, and the IAU chart license is explicit. It is an inference that the converted d3 segments retain attribution to the charts d3 says it used. For a public repository, keep the derivative separate from the MIT code; include the CC BY 4.0 text and the [BSD-3-Clause LICENSE](https://github.com/ofrohn/d3-celestial/blob/7e720a3de062059d4c5400a379146a601d9010e0/LICENSE); credit IAU, *Sky & Telescope*, Roger Sinnott, Rick Fienberg, Alan MacRobert and Olaf Frohn; and describe the GeoJSON-to-ZeroSky segment/identifier conversion. Do not include the chart images. The URL and access date of the unversioned IAU page should be recorded; the d3 commit pins the actual data used.

Import completed 20 October 2026: the GeoJSON source at the pinned commit has SHA-256 `294f66bef5d5cf50b1e17f16d2efa1d97a15131612c68dd935adef6e7373e13c`; [`build_lines.py`](../tools/catalog/build_lines.py) verifies it before conversion. [`constellations.tsv`](../assets/sky/constellations.tsv) contains 743 segments for 88 abbreviations. Vertices within 0.01° of HYG stars were matched to HIP identifiers; the two without reliable matches (`Cet`, `UMa`) retain J2000 RA/Dec. Notices are in [`CREDITS.md`](../CREDITS.md), the dataset and adjacent license files. The IAU page was accessed 20 October 2026: https://www.iau.org/IAU/Astronomy-FAQs/Constellations.aspx.

Latin names and label points come from d3-celestial's [`constellations.json`](https://github.com/ofrohn/d3-celestial/blob/7e720a3de062059d4c5400a379146a601d9010e0/data/constellations.json) at the same commit. Source SHA-256: `ab4ae692027cbc042c0d6791a84456a65eb7c55656107fd00c58ff6e55d4d8b2`. [`build_constellation_names.py`](../tools/catalog/build_constellation_names.py) verifies that hash and produces [`constellation_names.tsv`](../assets/sky/constellation_names.tsv): 89 points for 88 abbreviations because Serpens has two labels. The derivative retains the BSD-3-Clause and CC BY 4.0 notices and the same credits as the lines.

An alternative is Stellarium's [western sky culture](https://github.com/Stellarium/stellarium-skycultures/tree/master/western). Its [`description.md`](https://github.com/Stellarium/stellarium-skycultures/blob/master/western/description.md) declares **CC BY-SA** for text and data and the Free Art License for illustrations. The CC BY-SA version is not stated, so it was not selected for the lines. [HYG](https://github.com/astronexus/HYG-Database/blob/c7f7f883fe678cc7680169a50ccd7dcc49b060ce/hyg/CURRENT/LICENSE) is a star catalog, not a source of constellation lines.

### Magnetic declination at Gozo

Use **WMM2025** offline with latitude, longitude, altitude and date, rather than a constant for Gozo. The [NOAA package](https://www.ncei.noaa.gov/products/world-magnetic-model) provides modular C sources, `WMM.COF` coefficients and test values. `D` is declination in degrees, positive to the east; `F` is total field intensity, useful for detecting local disturbances. The coefficient file can be updated without changing the C algorithm. NOAA states validity through 31 December 2029 and explicitly calls its WMM code public domain. NOAA's recommended citation is *NOAA NCEI Geomagnetic Modeling Team; British Geological Survey (2024), World Magnetic Model 2025*, DOI [10.25921/aqfd-sd83](https://doi.org/10.25921/aqfd-sd83).

The vendored implementation uses NOAA modular C copied from a mirror and the standard `WMM.COF`, with exact hashes in [`VENDORED.md`](../third_party/wmm/VENDORED.md). The host test compares components and declination against [official NOAA values](https://www.ncei.noaa.gov/sites/default/files/2025-02/WMM2025testvalues.pdf).

Reproducible example using the vendored C: Victoria, Gozo (36.05° N, 14.24° E), **20 October 2026**, **0 m above the WGS84 ellipsoid**: `D = +3.85058°` east and `F = 44.8794 µT`. The wrapper passes three rows of the [official NOAA table](https://www.ncei.noaa.gov/sites/default/files/2025-02/WMM2025testvalues.pdf), including X/Y/Z components. Actual position and altitude slightly change the result; the app must compute it from current data rather than hard-code the Gozo example.

## Binary package audit

On 31 October 2026, the package built from the compass-calibration branch was inspected. Under `/usr/share/zerosky/` it contains `CREDITS.md`, `sky/LICENSE-CC-BY-SA-4.0.txt`, `sky/LICENSE-CC-BY-4.0.txt`, `sky/LICENSE-d3-celestial.txt` and `fonts/LICENSE.txt`. The HYG and OpenNGC derivatives share the first notice; the constellation data includes BSD-3-Clause and CC BY 4.0 notices. `cities.tsv` and the GeoNames CC BY 4.0 notice are included. CMake's `install(DIRECTORY ...)` copies these notices with the assets.

The package also contains **ten license and notice files** under `/usr/share/zerosky/licenses/`: ZeroSky, the ZeroRadio toolkit, Astronomy Engine, LVGL, LVGL's `COPYRIGHTS.md`, and the [QR code generator](https://github.com/lvgl/lvgl/blob/v9.5.0/src/libs/qrcode/LICENSE.txt), ThorVG, TJpgDec, TLSF and sprintf components bundled with LVGL. An earlier package lacked the MIT notices; the current install rules include them. The package path policy was run inside the Debian trixie container and reported `rejected paths: 0`. The final 1.0.0 `.deb` should be checked after its cross-build; the audit above describes the inspected package, not an unexamined release artifact.

The [GeoNames export README](https://download.geonames.org/export/dump/readme.txt) explicitly names CC BY 4.0 and `cities15000.zip`. The [`cities.tsv`](../assets/geodata/cities.tsv) asset says it was built 21 September 2026. The source archive's hash is **unknown**: attribution can be verified, but byte-for-byte reproducibility cannot. Inter and Phosphor carry full license texts in [`assets/fonts/LICENSE.txt`](../assets/fonts/LICENSE.txt). The exact revision of the individual TTF files is **unknown** and cannot be reconstructed confidently from this audit; record it in a future font manifest when those assets are updated.

## Import checklist

1. Record the tag or commit of each imported file in code or a manifest. HYG v4.1 already uses a pinned commit; an unpinned `CURRENT` path would move. Record the GeoNames export hash and font revisions if those assets are regenerated.
2. Keep Astronomy Engine's MIT notice; for derived constellation lines, keep d3-celestial's BSD-3-Clause and the IAU charts' CC BY 4.0 notices with attribution and a description of the changes. Record HYG and its transformations in the data manifest.
3. Do not copy Stellarium art or datasets without a specific license. Keep CC BY-SA data in files separate from MIT code.
4. Retain the NOAA WMM2025 tests as a numeric reference for the offline calculation.
